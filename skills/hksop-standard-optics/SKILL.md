## 版本保留规则（用户约定，2026-11-12）

本规则取代 2026-11-08 关于元件只留当前版、删除旧 CAD/图纸及不保留旧设计依赖的条款，适用于 HKSOP 和标准光学协议工作。其他项目历史、增量同步及存储约定继续适用。

- 引擎保留当前有效实现；现用元件进入正常选择列表。每次更新按用户当次明确指令选择“保留历史”或“不保留”；未说明时先确认，不擅自决定。首次新增没有被替换版本时无需此选择。选择保留时，旧版本及旧设计依赖的 CAD、图纸、俯视资源、BOM 与必要资料先登记到 `library/history`；选择不保留时，不归档本次被替换版本。
- 历史定义按原 ID、修订与来源哈希追溯，冻结其必要依赖；共享相同内容可以去重，但必须保留可解析的受保护引用。不得让同一旧身份静默改指新几何，不为保留少数依赖复制整库快照。
- `library/history` 中的元件供旧工程解析、渲染及使用原配套资料；不出现在新建元件选择列表，不允许从列表拖入或通过新增入口用于新设计。已有实例仍可打开和渲染，历史状态不能误作缺失或不支持显示。
- 更新记录用户当次的保留选择、旧工程的 ID、版本锁及实际依赖；选择保留时，验证历史文件可读、哈希和引用完整后再切换现用版本。旧工程不自动升级；未带足够版本信息时使用有证据的兼容映射，无法确定则报告，不猜测替换。
- 项目保留当前最终工程 JSON 和必要当前成果；项目 `history` 仍只放人工确认或正式交付的工程 JSON 里程碑。旧元件依赖统一进入 `library/history`，不为此保留全部旧引擎、项目模型、整套加工/客户包或自动保存。
- 入库事务可以清理已被正式采用或历史登记覆盖的临时回滚副本。`library/history` 及其引用资源不是缓存、孤立资源或清理候选；清理必须同时核对现用、历史及项目引用。
- 只增量保存新增/变更的当前资料和历史依赖，未变文件不动、不重复验收、不重压整库。外接盘的当前交付保留规则不得用于删掉历史依赖；历史版本以独立身份保留，并非被覆盖的同一当前交付。
- 保留来源、验收范围、项目引用与缺项记录；不以恢复文件冒充新的几何、实物或制造验收。未知或缺失依赖如实列出，不能声称旧设计已可精确复现。

先读 [工作区适配](../HKSOP_CONTEXT.md) 和 ../../docs/architecture.md。定位 library 的元件包或 projects 的确定修订，冻结输入哈希及库版本。

元件设计交给 hksop-component-design；本库登记交给 hksop-component-upload；加工和客户交付分别使用 hksop-manufacturing-package、hksop-customer-package。布局转三维继续使用 zzlab-optics-json-to-3d 的变换和核验要求。

使用根目录 hksop.py 生成总清单与运行目录；不要在 skill 中维护另一份支持元件表。项目的真实机械/光学验收、云端状态和本地编译状态分别说明。

AI 已验证的设计入库默认按 [验收复用与最小入库流程](../zzlab-optics-library/references/acceptance-reuse.md) 直接继承结论，只检查新增、变更及其影响；不重复设计验收或事务已完成的构建。
