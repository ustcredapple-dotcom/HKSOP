# 建模、核验、工程图与同步

## 可复建源

现有工程以厂家STEP、OpenCascade本地生成器和Onshape总装为主。延续适合当前任务的方式；原生Onshape特征能可靠编辑时可直接使用，不必为遵循旧脚本而导入不可编辑实体。

316L、去磁钝化是本项目定制转接件要求，不能覆盖商用品或他人正式柱的材料/表面规范；当前引用柱源记录为退磁、喷砂，应原样保留其来源说明。

在新工作目录中保留参数与源文件，不直接运行会覆盖正式文件的旧发布/打包脚本。运行前检查其输出路径、硬编码工作区和依赖；可复制为新修订并调整。新零件至少记录：

- 编号、修订、型号、责任范围、原始源路径与SHA256；
- 单位、功能基准、局部/装配变换、目标与实测光高/光面位置；
- 外廓与接触面、孔ID/轴/入口/螺纹或间隙/沉孔/深度、刻字；
- 定制件STEP、总装STEP、可复建源、工程图及其源模型哈希；
- 验证结果、限制、云端文档/元素/版本链接与NAS回执。

大型JSON先查看键名和所需字段，避免整份输出。旧构建脚本、说明中的运行状态可能只是中途快照；当前状态用最终交付回执和实际源核实。

## 模型验证

1. 检查每个新定制件的单位、实体数、闭合与几何有效性；声明“一体件”应为一个连续实体。复杂布尔/刻字后检查强几何或BOP诊断，不能只有“文件导出成功”。
2. 导出后读回STEP：比较实体数量、关键基准、孔径/深度/数量、包围盒与体积；变更较大或疑似几何丢失时，用功能主体的双向布尔差进一步定位。不是要求每次做无差别全量耗时矩阵。
3. 对每个不同几何/方位/高度配置核对实际光高、光学交点、销孔方向和螺丝配对。相同参数族可全量做轻量坐标检查，再对极值和碰撞风险配置做实体与工具路径检查。
4. 检查新定制件与柱、商用件、光束、主面包板、相邻镜架及接头的间隙。标明光束直径、工具包络尺寸和调节范围；只测某一范围就只报告该范围。
5. 厂家闭合弹性夹持模型与光学参考片的预期接触/重叠要分开记录。不擅自改商用模型消除警告，也不把所有穿透视为“厂家正常”。若无法解释，保留待核实状态。
6. 螺钉可预先放入；总装顺序写明。无需画紧固件，但检查头部通行、工具到达、螺纹啮合、底部余量及薄壁，不能只报孔中心对得上。

2026-10-11 用户确认：现有模型的编号凹字与功能刻线作为激光打标处理，不铣刻。约2.2 mm实际字高仅是既有样例，原0.2 mm凹深仅CAD显示参考，不能据此规定激光去除深度。标识避开承载接触、定位、薄壁和光路；编号与源文件一致，阶梯定位销免打标。按元件库技能的 [激光打标交付](../../zzlab-optics-library/references/laser-marking-delivery.md) 生成每零件/每面的真实毫米DXF与定位PDF，并在生产清单标出需求。不要为交付打标文件重建主体CAD或改变孔位。

## 加工图

先冻结源模型，再从同一源提取图纸。优先在Onshape提供可用工程图；若原生出图能力/格式限制，则生成详细PDF与DXF保存NAS，并可把图册导入Onshape分类展示。把“PDF附件”“DXF展示图”和“可编辑原生工程图”据实区分。

图纸至少包括：

- 单位mm、零件编号/修订、当前任务确认的材质与表面处理、投影法、比例和明确坐标基准；
- 三视图、主尺寸、台阶/凸台/退刀/倒角/圆角；隐藏加工特征需要剖视/局部/底视；
- 每类孔的数量、坐标及公差状态、入孔方向、通/盲、螺纹公称规格/螺距/有效牙深、沉孔直径/深度/入口侧；
- 盲孔有效圆柱深和钻尖余量，攻丝底孔与成品螺纹分别表达；不能从STEP中的一个圆柱直径猜测螺纹；
- 激光打标文字/功能刻线、实际尺寸、位置与阅读方向，明确不铣刻；CAD历史凹深不作为生产去除深度；
- 有证据的孔/螺纹等级、配合及尺寸专用公差；历史草图“待确认”不能在新图中静默变成已审签标准。

孔的加工规格必须直接标在对应视图上：引线端明确指向对应孔口、孔轴或剖视中的孔特征，写明孔径、螺纹规格/螺距及已确认等级、通/盲和深度，以及适用沉孔/沉头尺寸、深度或角度与入口侧。相同规格的组孔允许合并数量和规格标注，但必须能从引线、图面孔组范围或同规格说明唯一辨认全部成员，不能只给孔 ID 让加工者查表。孔规格表仅作补充与证据索引，不得代替孔旁加工规格；原图已有的坐标定位表及孔号可保留作为原定位方法。

孔位定位沿用原图已经使用的基准与表达方式，包括原有尺寸链、坐标定位表和孔号；不强制新增图面XY/XYZ定位块，区分零件局部坐标与装配坐标即可。入口方向、盲/通状态、有效牙深、有效圆柱深、钻尖余量和沉孔参数以当前版本的原生特征、原图纸、可信孔表或可测真实几何为证据；不由圆柱直径猜螺纹，不把钻深当有效牙深，不把两端钻尖相通当同径螺纹贯穿。未知值列为待核实，不能补猜后宣称加工图合格。普通视图无法明确表达入口、深度或相交孔时，增加底视、剖视或局部详图消除歧义。

逐页视觉验收须逐孔/逐组核对引线对应、孔位基准、规格、数量、入口与深度和真实模型/孔型证据一致，确认标注可读、不重叠、不裁切且不会指到邻孔。只有孔表完整、文字抽取命中或存在孔 ID 的图纸仍不满足该标准。更新已授权范围内既有不合格图纸时同样适用，不能仅给新图增加孔标。

### 紧凑孔/螺纹引出标注（2026-10-11 排版修订）

保留原图的基准、孔定位尺寸、尺寸链及投影方法；不要为了孔标重排原定位尺寸，或另用密集坐标清单取代原尺寸。规格放在对应孔旁的可用空白处，用短斜引线与短水平落脚线连接真实孔口/孔特征；箭头、字体、字高和对齐沿用图纸尺寸样式。一个孔标通常一至两行；需区分有效牙深和底孔深时允许紧凑第三行。禁止把来源SHA、核验声明、坐标列表、工具轴向向量或长加工说明堆在每个孔旁。来源、未决项与工艺说明放标题栏附近的统一说明或交付证据中。

同规格孔可用 `数量× 规格`，并按需要增加同规格孔的短引线；组内孔须从图面几何、阵列尺寸或已有孔标号范围明确识别。不要为每个孔组另加一整页。先在原投影面完成；确有拥挤、遮挡或入口/深度歧义时才加共用底视、剖视或局部详图，合并同一面的孔标。原有坐标定位表也是允许保留的定位方法；本轮不强制把表内坐标另搬上图面，也不新增全XYZ清单。孔的规格本身必须孔旁可读，不能仅查表确定孔型。

建议统一简写：`⌀` 表直径、`↧` 表已确认的深度、`⌴` 表圆柱沉孔、`⌵` 表锥形沉头；非螺纹贯穿孔可标 `通`；贯穿螺纹孔只标数量、螺纹直径×螺距及已确认等级（如 `4× M4×0.7`），不附 `通`、`通牙`、`贯穿`、`THRU`。盲螺纹保留有效牙深及必要的底孔深度。入口面与视图能唯一对应时不重复冗长方向说明；需区分双面加工时加 `顶面`/`底面`/源图面名。符号字体必须实际显示且可辨认，缺字时用短词“深”“沉孔”“沉头”，不能输出空框。保留已核实的配合/专用公差，不添加通用公差或粗糙度。

以下仅为排版示例，数值不是任何本次零件的加工尺寸，也不是Onshape强制的通用语法：

| 孔型 | 紧凑示例 |
| --- | --- |
| 同规格通孔 | `4× ⌀4.3 通` |
| 盲销孔 | `2× ⌀2.01 ↧4.2` |
| 通螺纹（螺距有源证据） | `4× M4×0.7` |
| 盲螺纹（深度分别有源证据） | 第一行 `2× M4×0.7 牙深5.5`；第二行 `底孔 ⌀3.3 ↧7` |
| 圆柱沉孔 | 第一行 `4× ⌀4.3 通`；第二行 `⌴ ⌀8.25 ↧4 顶面` |
| 锥形沉头 | 第一行 `2× ⌀4.3 通`；第二行 `⌵ ⌀8.5×90° 顶面` |

螺距、牙等级、深度、沉头角度与数量必须来自当前可信孔特征/图纸/规格；没有证据就不填。钻尖深和有效圆柱深不同，不从螺纹公称直径猜底孔，也不从圆孔猜螺纹。缺少关键加工参数时在统一未决说明登记并保留审核状态。Onshape原生Hole/Thread Callout优先取孔特征元数据；自绘图按同样的证据关系和短引线布局实现。依据：[Onshape Hole/Thread Callout](https://cad.onshape.com/help/Content/Drawing/hole_thread_callout.htm)（元数据、同规格多引线及样式设置；不规定上述示例的通用语法）。


用户要求不标通用公差和粗糙度，属于有意省略，不自动加回或列为待确认缺口；保留已有证据的孔/螺纹等级及尺寸专用公差。

现有后端采用第一角法：俯视在主视下方、右视在主视左方。若换投影法，符号、布局与视图方向同步。尺寸表以零件局部坐标为准，必须与装配世界坐标区分。

生成后逐页渲染检查：孔ID能对应视图、所有文字可读、线型正确、表格不裁切、单位/方向/深度不矛盾；检查PDF全部页面而非仅封面。使用环境中适用的PDF工具/skill，不把单次渲染成功当成图纸核验完成。

本项目有标准DXF与Onshape兼容展示副本：标准版保留真实可编辑尺寸，展示版可将中文转字形、隐藏线转实际断线以适配导入器。两者明确命名，展示副本不能替代标准加工DXF。Onshape出现图纸标签，不等于其全部图页已验证。仅修改图纸说明时保持冻结CAD不变，避免无意重建导致源哈希漂移。

## Onshape分类与确认

使用当前环境已提供且获授权的Onshape工具或浏览器控制。无需为了整理本地skill打开云端；实际建模交付时才操作对应文档。浏览器工具遵循其公开API，不能用页面隐藏状态、登录cookie或猜测的内部接口代替工具授权。

修改前保存可恢复版本。沿用既有类别，在对应器件下分别放：定制单件、总装、工程图；厂商/STEP导入源放参考目录，旧版放历史目录。不要再次把大量标签摊在根目录；也不要靠重命名把旧件冒充新件。

导入一次后等翻译完成并确认真实状态；遇到超时先核对是否已生成元素，避免重复。失败可针对单文件修复后重导；重复失败时保留本地完整交付和诊断，不盲目无限重试或删除全部旧源。登录/锁屏阻挡时可继续本地工作，但云端状态明确为未完成。

核验代表性单件和总装：零件数量、实际形状、导入警告、引用版本、分类、命名；关键新定制件必要时从云端导出回读。已成功的原始源/装配不要因某个商用参考叶子的警告全部推倒重来。

保存最终版本和可访问链接；截图证明要来自实际云端结果。STEP总装导入没有配合关系时，称为固定位置的导入总装，不声称具有可运动的原生配合。说明哪些是定制加工件、哪些只是商用参考。

既有可靠STEP结构为顶层保留真实零件叶节点及`COMPONENTS`子装配；纯扁平STEP曾只生成Part Studio。可参考当前导出器，实际确认云端生成Assembly，不凭STEP里有装配关系就报告已建总装。

## NAS与交付

给师傅的加工包遵守 [加工包默认规范](machinist-package.md)：一种加工件一个目录，根目录只放简洁加工清单，按可制造/可定位的信息完整性核对。下面的完整资料保留要求用于内部设计归档，不增加师傅包的内容。

每批修订建立独立内部归档目录，保留单件、总装、工程图、原厂来源、可复建源码/参数和核验记录。不要覆写旧版或把新图与旧STEP混包。

校验复制后的文件数量和哈希；ZIP检查成员与CRC，必要时逐成员SHA，并核对NAS副本。NAS不可用时保留本地结果并准确报告。只报告实际完成的地方：上传交接JSON或存NAS不代表网站发布成功。

先确认NAS确实挂载，不能在不存在的挂载点创建本地同名目录冒充NAS。含`62.5`的包名用`Path(str(package_dir) + '.zip')`追加扩展名，避免`with_suffix()`截掉小数点后的目录名。哈希清单不自包含其自身哈希；可复建脚本和参数进入内部归档，不放进师傅加工包；商业字体文件不随包复制。

最终答复提供当前Onshape版本、图册/资料包路径和少量关键变化，说明影响使用的未决项。几何验证与实测装配结论分开；不要隐藏相机感光面估算、未定加工公差或商用导入警告。

规范依据仅限已查公开资料：[ISO 15786:2008](https://www.iso.org/standard/42099.html)的公开scope覆盖孔、沉孔、内螺纹和倒角的简化表示与标注；[ISO 129-1:2018](https://www.iso.org/standard/64007.html)的公开scope/目录覆盖尺寸表示、引线和表格尺寸。结合[Onshape Hole/Thread Callout](https://cad.onshape.com/help/Content/Drawing/hole_thread_callout.htm)公开文档作为排版参考。未取得并逐条审核标准全文，不宣称ISO认证、逐条合规或Onshape原生导出；不据此增添原来源未指定的6H等螺纹等级。
