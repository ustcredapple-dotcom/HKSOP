# 元件化与交接

读取当前项目 schema、`tools/library.py --help`及导入协议。编辑正式源记录而非只编辑生成catalog。

1. 新加工件/架构用新稳定ID；记录局部坐标、材料、尺寸、STEP SHA、制造状态和源。修改既有记录绑定 previousSha256，保留旧模块及光学报告。
2. BOM 完整列当前原镜架、电机、杆/套/盖、支撑、柱/转接。旧板组/轴套不自动购买。标准螺钉按项目规则计价，另给完整数量与装配表；不含五金的STEP不能声称含五金。
3. 光学槽用实际口径，光面由真实后座和指定镜厚计算。SVG用实际CAD投影，碰撞轮廓包含支撑和五金包络。标准光高不是器件实测。
4. manifest绑定记录、资产、源及来源/几何/交互/BOM审阅；实际stage→adopt dry-run→apply→build→派生索引→strict。记录最终SHA、日志及未执行项。
5. 按接收端catalog与运行源码指纹核分支，保留R3/AOM和实例能力。兼容包显式精确版本链，先只读，验证正常失败完整回滚；不能改清单绕过拒绝。
6. 元件库/内部交接保留协议、CAD/图纸、生成器/参数/依赖说明、源记录、安装器/实际验收及需要的图册。给师傅的加工包另按 [加工包默认规范](../../zzlab-modular-optics/references/machinist-package.md) 组织，不把这些内部材料混入。最终ZIP做CRC、安全解压、完整文件集合/SHA核对；NAS最终名下读回。NAS成功不代表网站或云端更新。

## 加工图孔标验收

采用当前项目 `zzlab-optics-library/references/source-manufacturing.md` 的图面孔标与定位验收，以及 `zzlab-modular-optics/references/build-and-deliver.md` 的加工图规则；接收端没有安装技能时使用项目附带的当前协议，不依赖某台电脑的绝对路径。

孔的加工规格必须直接标在对应视图上：引线端明确指向对应孔口、孔轴或剖视中的孔特征，写明孔径、螺纹规格/螺距及已确认等级、通/盲和深度，以及适用沉孔/沉头尺寸、深度或角度与入口侧。相同规格的组孔允许合并数量和规格标注，但必须能从引线、图面孔组范围或同规格说明唯一辨认全部成员，不能只给孔 ID 让加工者查表。孔规格表仅作补充与证据索引，不得代替孔旁加工规格；原图已有的坐标定位表及孔号可保留作为原定位方法。

孔位定位沿用原图已经使用的基准与表达方式，包括原有尺寸链、坐标定位表和孔号；不强制新增图面XY/XYZ定位块，区分零件局部坐标与装配坐标即可。入口方向、盲/通状态、有效牙深、有效圆柱深、钻尖余量和沉孔参数以当前版本的原生特征、原图纸、可信孔表或可测真实几何为证据；不由圆柱直径猜螺纹，不把钻深当有效牙深，不把两端钻尖相通当同径螺纹贯穿。未知值列为待核实，不能补猜后宣称加工图合格。普通视图无法明确表达入口、深度或相交孔时，增加底视、剖视或局部详图消除歧义。

逐页视觉验收须逐孔/逐组核对引线对应、孔位基准、规格、数量、入口与深度和真实模型/孔型证据一致，确认标注可读、不重叠、不裁切且不会指到邻孔。只有孔表完整、文字抽取命中或存在孔 ID 的图纸仍不满足该标准。更新已授权范围内既有不合格图纸时同样适用，不能仅给新图增加孔标。

### 紧凑孔/螺纹引出标注（2026-10-11 排版修订）

保留原图的基准、孔定位尺寸、尺寸链及投影方法；不要为了孔标重排原定位尺寸，或另用密集坐标清单取代原尺寸。规格放在对应孔旁的可用空白处，用短斜引线与短水平落脚线连接真实孔口/孔特征；箭头、字体、字高和对齐沿用图纸尺寸样式。一个孔标通常一至两行；需区分有效牙深和底孔深时允许紧凑第三行。禁止把来源SHA、核验声明、坐标列表、工具轴向向量或长加工说明堆在每个孔旁。来源、未决项与工艺说明放标题栏附近的统一说明或交付证据中。

同规格孔可用 `数量× 规格`，并按需要增加同规格孔的短引线；组内孔须从图面几何、阵列尺寸或已有孔标号范围明确识别。不要为每个孔组另加一整页。先在原投影面完成；确有拥挤、遮挡或入口/深度歧义时才加共用底视、剖视或局部详图，合并同一面的孔标。原有坐标定位表也是允许保留的定位方法；本轮不强制把表内坐标另搬上图面，也不新增全XYZ清单。孔的规格本身必须孔旁可读，不能仅查表确定孔型。

建议统一简写：`⌀` 表直径、`↧` 表已确认的深度、`⌴` 表圆柱沉孔、`⌵` 表锥形沉头；通孔/通牙用 `通`，盲孔用深度标记及必要的 `盲`。入口面与视图能唯一对应时不重复冗长方向说明；需区分双面加工时加 `顶面`/`底面`/源图面名。符号字体必须实际显示且可辨认，缺字时用短词“深”“沉孔”“沉头”，不能输出空框。保留已核实的配合/专用公差，不添加通用公差或粗糙度。

以下仅为排版示例，数值不是任何本次零件的加工尺寸，也不是Onshape强制的通用语法：

| 孔型 | 紧凑示例 |
| --- | --- |
| 同规格通孔 | `4× ⌀4.3 通` |
| 盲销孔 | `2× ⌀2.01 ↧4.2` |
| 通螺纹（螺距有源证据） | `4× M4×0.7 通` |
| 盲螺纹（深度分别有源证据） | 第一行 `2× M4×0.7 牙深5.5`；第二行 `底孔 ⌀3.3 ↧7` |
| 圆柱沉孔 | 第一行 `4× ⌀4.3 通`；第二行 `⌴ ⌀8.25 ↧4 顶面` |
| 锥形沉头 | 第一行 `2× ⌀4.3 通`；第二行 `⌵ ⌀8.5×90° 顶面` |

螺距、牙等级、深度、沉头角度与数量必须来自当前可信孔特征/图纸/规格；没有证据就不填。钻尖深和有效圆柱深不同，不从螺纹公称直径猜底孔，也不从圆孔猜螺纹。缺少关键加工参数时在统一未决说明登记并保留审核状态。Onshape原生Hole/Thread Callout优先取孔特征元数据；自绘图按同样的证据关系和短引线布局实现。依据：[Onshape Hole/Thread Callout](https://cad.onshape.com/help/Content/Drawing/hole_thread_callout.htm)（元数据、同规格多引线及样式设置；不规定上述示例的通用语法）。


用户要求不标通用公差和粗糙度，属于有意省略，不自动加回或列为待确认缺口；保留已有证据的孔/螺纹等级及尺寸专用公差。

报告分别写名义避让、浮动/旋转、制造待定、实物/电动行程、软件安装、NAS、Onshape状态；按用户当前授权交付，不额外驱动实机或发布。

规范依据仅限已查公开资料：[ISO 15786:2008](https://www.iso.org/standard/42099.html)的公开scope覆盖孔、沉孔、内螺纹和倒角的简化表示与标注；[ISO 129-1:2018](https://www.iso.org/standard/64007.html)的公开scope/目录覆盖尺寸表示、引线和表格尺寸。结合[Onshape Hole/Thread Callout](https://cad.onshape.com/help/Content/Drawing/hole_thread_callout.htm)公开文档作为排版参考。未取得并逐条审核标准全文，不宣称ISO认证、逐条合规或Onshape原生导出；不据此增添原来源未指定的6H等螺纹等级。
