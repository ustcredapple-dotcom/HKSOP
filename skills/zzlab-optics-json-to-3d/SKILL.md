## 版本保留规则（用户约定，2026-11-08）

本规则优先于本 skill 及其旧参考文件中要求永久保留全量版本、旧快照、旧 CAD 或整批历史交付的条款，适用于 HKSOP 和标准光学协议工作。

- 引擎只保留当前有效实现；元件库只保留当前有效定义及其正在使用的 CAD、图纸、渲染与必要说明。不同现用型号/安装变体可以共存，不能仅凭文件名含 R1/R2 就认定为历史。
- 具体项目保留当前最终工程 JSON、当前最终 3D/CAD、图纸、加工包、客户包及采购清单。只在当前项目确实需要时保留这些成果。
- 历史版本只保留具体项目人工确认或正式交付的工程 JSON 里程碑，并按内容去重。不要保留自动保存、临时调试或元件入库演示的全量历史。
- 不保留旧引擎、旧元件库快照、旧项目 3D 模型、旧 CAD/图纸、旧加工/客户包或整套旧复建资料。不能为打开历史 JSON 而暗中保留这些历史依赖。
- 历史 JSON 仅用于布局追溯；重开时对照当前元件库检查兼容性，不能宣称可精确复现已删除的旧几何。当前实际项目专用元件应作为现用定制元件正式登记，而不是用整库历史快照承载。
- 入库事务允许短期回滚暂存；成功完成并验收后立即清理。生成目录、缓存和过期暂存不作为永久版本。
- 完整备份也只包含上述保留集合，不能再次把全部历史版本收进备份。更新前核对当前依赖，更新后核对文件和链接、重新生成目录大小报表。
- PROJECT_LOG、版本号、来源哈希及验收结论可保留为精简文字记录，不等于保留旧版实体文件。整理限定在本次获授权的工作区，不自动扩大删除其他原项目、服务或数据库。

## 必须保持的建模约束

1. 从实际实例的 `boardId`、板参数和 kit/CAD 基准解析孔距、板位置、全局 `supportZ`、光高及旋转。`baseMode: table` 的根板可能只是桌面参考，不能代替真实子板。
2. 从柱轴、真实支撑面、安装孔、真实光学面建立局部坐标。禁止用包围盒猜安装或光学基准；禁止缩放厂家件或据截图重新造件。只使用 `RᵀR = I`、`det(R) = +1` 的刚性旋转和平移，保留厂家 B-rep 与 trim 参数。
3. 一个 kit 定义保留完整内部层级，重复实例复用该定义但各有 occurrence 及实例 ID。内部件名可能重复，不能只按显示名称合并实体。
4. 未知 kit、缺 CAD、缺基准或不支持的 JSON 能力须记录缺证及受影响实例。不能凭项目名补激光器本体、镜片、光学镀膜或采购型号；没有证据的内容留待补齐。
5. 在 `/Users/Shared/ZZLAB/OpticsKits/cad-venv/bin/python` 的已知 CAD 环境复建，当前冻结环境为 `cadquery-ocp 8.0.1.0.0`。生成器属于模型工作记录，按登记引用，不复制到 skill 内。

## 三维光线

只有网页确实已渲染光路、且相应光学元件已装配的部分才渲染三维光线；网页未显示或元件未装配的部分不生成。先读 JSON 光学配置并核查网页光路和实际光学元件，不能根据文件名、机械占位或单个 `visible` 标志猜光路。

保存的 `generated=false` 可能是旧状态。用户当前网页截图或实际网页状态已证明光路显示时，以该证据判断；用户明确要求按新光学参数重建时，记录该指示后可计算光路。光学件被标为已装配但缺真实 CAD 尺寸时，只能显示明确标注的名义光学面，不能补造玻璃厚度或制造件。

光线粗细按实际物理光束参数建模，区分光束直径、waist、divergence 等 mm/rad 参数与网页 px 线宽。保留参数来源与直径定义；缺实际光束参数时向用户获取或记录待补，不能用默认粗柱并宣称真实粗细。各版状态见登记，不能把 R1 无光线的历史状态推广为未来都不渲染。当前光束由保存的参数计算，并非实测束径；器件移动后须重新计算光路再导出，静态 STEP 不会自动追迹。

## 核验、云端与交付

独立读回 STEP，核对实例与源层级、叶与闭合 solid occurrence 数、单位、局部/全局基准、安装孔和光高；保留真实几何有效性、bounds 和严格体积比较结果。任何失败均按原阈值留档，不能放宽阈值把失败变通过，也不能未经几何证据把差异全归为数值积分。

2D `collisionOverrides` 只是保存的布局豁免；逐组 3D 筛查的结论只能覆盖所查对象。完整干涉、通光、操作空间、图纸和制造放行需要对应验收证据，不能从 AABB、预览或 STEP 可读推导出来。

仅在用户要求云端操作时上传/装配。使用正常授权工具；工具或安全检查不可用则保留错误和未完成项，不绕过。STEP 层级不等于 Onshape mates；必须云端实查完整子装配数量、刚性组锁位与原机构自由度、板固定及整套实际移动后，才可称云端装配完成。一次工具故障不构成以后每次都须额外授权的规则。

交付正式输出、复建资料、预览与验收记录后，按所在项目的日志约定留档，并实际核验后更新 `latest-model.json`：新版本追加到 `models` 并更新 `latestModelId`，同一版本的迁移/验收/云端进度追加 `statusHistory`，保留旧版本、旧状态及 SHA。不在迁移尚未核验时删除生成副本、输入或依赖。
