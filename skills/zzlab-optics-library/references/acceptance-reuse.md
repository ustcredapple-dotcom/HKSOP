# 复用已有 AI 验收与增量入库

用户约定（2026-11-09）：AI 已经验证过的设计直接复用原验收，只检查新增、变更及其直接影响的部分，不重复验证。本规则适用于普通入库、快速入库和设计交接，优先于旧参考文件中无差别重跑全部检查的条款；无需用户每次再指定“简化模式”。

## 最小流程

1. 读取当前设计的完成回执、清单或项目日志，确认型号、修订和适用文件。沿用已有源版本、文件哈希及验证来源；只核对本次输入与新增/变更资源的身份，不重新扫描或哈希全库。已有记录足以对应当前成果时直接引用，不要求重写整套验收报告。
2. 沿用已完成的几何、孔位、工具通道、光高/光学面、图模一致性、BOM、渲染等结论以及对应资产。只列本次新增/改变的记录、文件、接口、依赖和运行行为；换目录、打包或登记本身不使未变设计的验收失效。
3. 只补缺少的入库字段和资源。设计包已有合格的 package.json、俯视图、图纸与证据时直接使用；不重建模型、不重画图、不重复渲染、逐页复看 PDF 或重新测量已验证的几何。
4. 按当前项目工具完成 package check → stage → adopt，保留 ID、资源引用、BOM、基线和依赖兼容性门控。事务内自动完成的校验及 catalog/runtime 构建直接复用，不再单独重复运行。仅缺少运行产物或相关输入已改变时补一次必要构建。
5. 只检查本次新增/变更的入库映射与尚未覆盖的运行行为，例如新资源能否解析、新 kit 的摆放/吸附、交互或下载引用。相同版本和运行环境下已有验收直接引用；未变元件和未受影响的行为不复查。不为重复确认同一结论启动浏览器、服务、全库回归或整套 CAD 验证。工具事务内必需的全库契约校验保持原样，无需再人为增加第二轮。
6. 在现有入库回执或项目日志中简要记录：沿用的来源/版本、此次新增或变更、实际补做的检查、仍未完成的项目。明确“沿用验收”和“本次执行”，不把继承结果写成刚刚重新测试。

## 何时追加检查

只有新增内容、内容改变、依赖或运行契约不兼容、证据缺失或明确矛盾时才检查相应部分。先确定具体影响范围：例如孔位改变检查有关孔组与装配通道；光学面改变检查有关基准和交互；仅新增资源路径检查路径解析。缺一项证据只补该项，不以此启动全套复验；未完成且不阻断本次入库的能力可继续保留待验收。

已有“名义几何通过、未实物试装、未全行程测试、未制造放行、未同步云端”等状态原样继承。复用验收不会提高验收等级。网站、Onshape、图册或其他发布只按用户指定范围执行；若目标本身有新增/变更，只核验该目标的新结果，不重验原设计。

## 设计端交接

交付当前源/修订、已有清单与哈希、验证记录、适用范围和未完成项；已有材料直接引用。设计修改只更新受影响文件和检查，并沿用其余结论。为入库准备过的 package.json、BOM、俯视图和加工图一并复用，接收方不重新执行同一套设计验收。
