# 标准套件极速上传

当用户选择“极速上传／快速入库”，或要求标准生成包只做可用性核对、不要图册与 Onshape 时，采用此模式。用户 2026-10-16 明确要求上传后可直接拖入网站和本地编辑器画布。

这是轻量发布范围，不称“标准协议全部验收完成”。普通完整入库与本模式均遵守 [验收复用规则](acceptance-reuse.md)，只补新增/变更的未覆盖检查。不能先答应极速模式，又自动补做全库 CAD、云端或整册验收。

## 保留的检查

- ZIP 能完整解压，成员 CRC/清单 SHA 一致；读取生成工具的完成回执，绑定包哈希、工具版本和原套件基线。不要执行压缩包内的脚本。
- 新套件 ID 不重名；BOM 身份、数量和选配引用有效；新 STEP、加工 PDF、已有打标文件可读取。复用原生成工具已完成的几何检查与已核准的原器件资料，不重新设计。
- 可放置必须有真实新总装俯视图、毫米图框、柱中心锚点、底座与安装孔、实际轮廓及光学数据。角度工具的包原本 `placementAllowed:false`，不能只翻成 true，也不能旋转整张旧图：固定底座/孔位不转，上装和光学面/方向/内部端口随真实刚体变换转动。
- 用现有光路解释器检查新记录；未知物理参数和原有“不支持模拟／待实测”状态继续保留。不能为了“可用”补造光心、口径、镜片或制造批准。
- 只补新套件在当前运行环境中尚未覆盖的拖放、安装孔吸附、相关光路配置和下载引用检查；相同版本/环境下已有验收直接引用。未变旧套件、旧图册和云端对象不重复验收。

## 现有角度工具接入

项目 `tools/fast_kit_upload.py` 接收 `zzlab-simple-kit-rotation-v1` ZIP 及同目录 `DELIVERY_RECEIPT.json`。`tools/fast-kit-templates.json` 登记已接纳的 66 个基线与两版几何生成器哈希；这是兼容性范围，不是所有角度实装证明。

用项目已安装的 OCP/VTK CAD Python 运行（还需 numpy、shapely、pypdf）：

```text
CAD_PYTHON -B tools/fast_kit_upload.py 完整资料包.zip --output 新建工作目录
```

产物：`package/` 标准导入包、`stage/` 候选真源/目录/新增文件、`preview/` 真实俯视图、`receipt.json` 实测耗时与结果。它不会上线、改云端、更新图册或写用户工程。

未知生成器、变更过的基线、缺回执、BOM 不一致、不能确定坐标变换等，仅列出这个包的具体缺项。能局部补齐就补齐，不要无提示转为数小时全流程；超出既有接入器的包先写相应适配器。没有指定某个包/角度时，只建流程并做隔离测试，不把随机测试角度发布进正式库。

## 增量发布

`tools/fast_kit_publish.py` 复用相同运行代码，添加候选真源、目录、新文件和索引；用 APFS 写时复制生成运行发布，NAS 只接收并回读本次 delta。首次使用附带一次已按前后 SHA 登记并验证的总装参考导出补丁；后续数据包复用它。固定源发生并行变化会停止，重新针对当前版本准备。此模式不调用普通部署的整库 NAS 重复制。

```text
SERVICE_PYTHON -B tools/fast_kit_publish.py 工作目录 --out 新建增量目录 --node NODE
SERVICE_PYTHON -B tools/fast_kit_publish.py 工作目录 --out 另一新建增量目录 --node NODE --apply
```

第一条只准备可审查增量。第二条在用户已授权发布具体包时执行；`--apply` 不是额外审批要求。它会切换网站、检查新套件图片/摆放/下载及原认证边界，并同步现有本地编辑器；失败恢复原发布与本次源改动。使用前阅读实际错误，不跳过基线锁或哈希门控。

网站和本地编辑器的现有认证、账号、数据库、购物车、工程和光路引擎不随极速上传更改。无须为新套件修改画布引擎。应用代码或新交互协议改变时，另做对应发布，不能混入数据增量。

## 图册、云端和归档

- 新记录注明 `fastUpload`、图册未收录、Onshape 未上传；保留“加工审核版／未实物验收”状态。
- 沿用已验收图册 PDF，SHA 和页面不变。`assets/drawings/atlas/current.json` 明确保存图册实际覆盖基线 `coverageCatalogSha256`、排除套件/新单件清单和 `pdfRegenerated:false`；网站入口显示“标准库图册（不含极速上传）”。目录绑定更新不能被表述为图册已更新。
- NAS `CURRENT_RELEASE.txt` 继续指向完整基线；有效 `CURRENT_FAST_RELEASE.json` 描述该基线加有序 `deltas/` 链。恢复时先取完整基线，再顺序应用各 delta，逐文件核对前后哈希。只有 `fullBaseRelease` 与当前完整基线相符的快速指针才有效。
- 保护完整基线和当前 delta 链，不因“旧版”而删除恢复依赖。下次完整发布可合并成新基线，再按存储政策解除旧链保护；不为极速上传自动做整库归档。
- 项目日志记录具体包、图册/云端排除范围、实测检查与发布耗时、网站/本地编辑器状态、NAS 回执及恢复依赖。不能把生成/准备耗时当作已经完成线上发布的耗时。
