# 元件导入协议 v1

协议标识：`zzlab-optics-library-v1`。运行目录版本继续使用 `catalog.version`；工程文件继续使用 `zzlab-optics-project` v1。三者各管自己的兼容性，不相互替代。

已有 AI 验收按 [验收复用与最小入库流程](acceptance-reuse.md) 直接继承；以下检查仅补新增、变更及受影响的未覆盖部分，优先于旧条款中的重复验收要求。

## 身份与数据所有权

| 对象 | 定义位置 | 含义 | 不能代替 |
|---|---|---|---|
| component | `library/records/components/<id>.json` | 一种采购件或自制件；型号、数量单位、材料与制造文件 | 整套安装位姿 |
| kit | `library/records/kits/<id>.json` | 可选套件/整装；BOM、选配槽、真实几何和光学基准 | 用户放置的实例 |
| registeredBoard | `library/records/boards/<id>.json` | 特定外形的板；孔表、外形、厚度、制造资料 | 任意宽高参数板 |
| catalog metadata | `library/catalog-meta.json` | 分类、全局光学选项、已登记柱系列、材料等目录级定义 | 用户参数的默认覆盖器 |
| instance / subBoard | 工程 `layout` | 局部坐标、旋转、器件状态、小板归属 | 全库默认设置 |
| optical settings | 工程/实例中的 `optics`、`internalOptics` 及选配映射 | 当前插入的晶体、source角色、实际光学参数 | 固定 BOM 的隐式复制 |
| cart / shared project | 独立 SQLite 用户状态 | 加入时的方案与清单快照/发布的模块 | 本次目录迁移的编辑目标 |

记录的 `id` 一经被工程或 BOM 引用就保持稳定。名字可改，ID 不跟随中文名字变化。替换实物版本需登记来源/资产变更并验证购物车旧快照的版本拒绝行为；不静默将旧订单替换成另一件实物。

## 输入包

使用 `tools/library.py package-template` 生成当前机器格式模板，先运行 `--help` 确认参数。包内包含记录、资源增量和审核证据；精确字段由项目 `library/schemas/` 和 CLI 校验器定义。

每个条目至少回答：是什么对象、来自哪里、谁负责/是否允许本次改动、与哪些已有对象相同、改变了哪些字段、什么能力已验证、缺少什么证据。新增用 add；覆盖既有 ID 或同路径资源须显式 replace 并绑定旧 SHA256。元件包带基线目录指纹，避免另一个 AI 的更新被覆盖。

运行资源保存在 `assets/`（模型、图纸、供应商模板等）或 `static/`。普通元件导入包只允许修改 `assets/step/`、`assets/drawings/` 和 `static/topviews/` 中的受支持文件；原始报告、截图等审核资料放包内 `evidence/`，采用后归档到 `library/reviews/`，不能借元件包替换网站脚本或供应商模板。

资源路径使用逻辑根下的相对路径。拒绝绝对路径、`..`、逃出逻辑根的链接、类型不符和校验和错误。根内链接即使可以读取，发布文件也必须是物化后的普通文件；发布器拒绝包含符号链接的目录。内部工作目录和账号信息不进入可公开元件包。

来源审核、几何审核、交互审核和 BOM 审核分别给出审核人、状态、原因和带 SHA 的证据文件；不适用时也写原因与依据。单个布尔值不能作为审核记录，检查器会拒绝。完整记录仍是提供者声明，不代替所引用 STEP、报告页、截图、测量或测试结果。商业激光器没有制造 STEP 可以合理不适用；可加工自制件缺 STEP/PDF 是未完成，不能标不适用。

## 从资料到候选库

1. 记录原始文件哈希、Onshape 文档/元素/版本或报告页码。若是 Main 工作区，另记录获取时间并优先冻结版本；不能把任意已有版本名当成导出文件来源。
2. 去重单件，再建立 kit 的每套 BOM。相同组件多套使用同 ID；装配数量由完整引用展开得到，隐藏/抑制/素材/CAD导入是否纳入按当前任务与真实装配核对。
3. 登记安装坐标、孔、底座、碰撞边界、光学面或出光口。图片尺寸/anchor 与实体坐标一致，安装基准与光学基准分开。
4. 配置交互能力与选配槽。普通镜架、波片、PBS、耦合头、激光源、复合三维总装、仅参考器件分别按既有适配器处理；不以“未知类别兜底成透镜”作为新元件实现。
5. 制造资料和采购资料分开验收。光学片选填可空，螺钉未知可空；不猜 SKU、螺纹、材料或粗糙度。已知来源覆盖全局默认时保留明确的来源与适用范围。
6. 运行 stage 的只读检查或写入独立候选目录；保留 schema、引用、哈希和 BOM 契约门控；只补新增/变更运行行为与图像/PDF的未覆盖检查，已验收未变文件不重复打开。
7. 基线未变且审核通过后采用候选；事务已完成的确定性构建直接复用，再按任务要求发布。发布前 `build --check` 必须通过；既有一次性脚本不能绕过该入口。

安装策略例外须逐 kit 记录来源，不能修改几何来实现。`layout.baseOverhangAllowedWithPartialMounting` 只允许布尔值；启用时 `minimumAlignedMountingHoles` 必须明确为至少 2 且不超过不同真实安装孔数量。运行时仍必须找到足够的有效 M6 板螺纹孔，不能使用沉孔、普通通孔或根桌面的虚拟孔。当前只有旧版 `waveplate` 使用 2026-10-06 用户指定的两孔部分悬出规则，来源记在 `layout.baseOverhangPolicySource`；这不代表其他波片或同底座器件自动适用，也不是承载验收。完整行为与反例见交互协议第 3、4 节。

## 能力与未知值

至少分开检查 display、placement、simulation、procurement、manufacturing。这些是协议中的验收维度，不随意向当前 API 塞入未支持字段。

- 参考图片能显示但尺寸未核验：不声称可安装；缺出光口高度时不伪装成已配平光源。
- `placementAllowed:false` 或 `bomPolicy:reference-only` 的实际意义按现有代码保留。
- 只有所选自制件具备所需 STEP/PDF，制造 ZIP 才可完整导出；未选的缺图件不阻止其他件。
- 缺镀膜相位、焦距、NA或机械入口数据时保留计算边界，不能以默认数据冒充厂家实测。
- 旧库 migrated/legacy 表示“按原记录整理”，不表示逐件完成了新的实物复测。待补证据必须单列。

## 验收证据

生成 asset-index（实际文件/SHA/被哪些记录引用）、catalog-audit（结构与统计）、evidence-gaps（缺口）、interaction-index（有效交互规则和来源）。几何调整应额外带 before/after 来源、改变的孔组或基准、保持不变项、测量脚本/报告、导出图纸与 STEP 一致性。不要为了补齐审计字段虚构日期、设计者、制造级别或测量精度。

协议更新采用版本号和兼容说明；实例工程的破坏性迁移需独立验证。现有 v1 用户工程、账号购物车、旧资产备份不是目录整理时可随意清理的数据。

自 2026-10-08 起，标准光学协议的组装件交付验收增加 [Onshape 光学元件库](onshape-library.md)：本次范围内的所有组装件进入名为“光学元件库”的同一云端库，每个需上传的当前组装件 kit/构型/修订一个完整独立装配体，全部自制散件另列“自制散件”文件夹。按 2026-10-08 用户要求，本库排除旧英制柱单件，当前公制组装件不得夹带旧英制柱，不另建云端历史柱文件夹；原本地源与证据保留。按正式 `registry.json` 记录稳定 ID、精确源 record SHA/目录版本、几何身份（导出 CAD SHA 或已核真实几何的冻结 `nativeGeometryIdentity`）、真实目标元素及冻结版本；原生复制保留依赖、mates/自由度出处，未生成导出文件时 CAD SHA 为 null 并写真实原因，不能通配或任取首条原生来源。并逐项实查上传/转换、层级与 BOM、内部姿态/机构自由度、整体移动及 Undo、尺寸基准和散件归档。未上传、转换失败、缺 CAD 或工具阻断分别保留状态和原因；本地检查通过不能代替云端验收。新增或更新按当前最新 record、实际修订及完整 CAD 上传；目标为已实查的普通 Student Folder“光学元件库”，允许文件夹内多文档及子文件夹，各条目分别登记真实 document/workspace/version/element/configuration，不强制全库共用一个 documentId。用户已要求更新直接删除被替换的旧云端库副本；先确认最新上传/转换、精确身份及完整定义可用，并先重绑当前共享依赖，随后直接清理旧 Assembly/散件 tab、复制文档或旧入口，记录 deleted/inactive 和实际删除 ID，禁止 JSON→3D 回退到已删旧云端目标。原设计、本地冻结来源和不可删除的平台 history 保留可追溯事实。该要求是旁置交付协议扩展，不改变 `zzlab-optics-library-v1` 数据 schema 或已有工程兼容性。


## 机加工总图册交付与更新

按 2026-10-09 用户要求，每次新增/更新器件的标准协议验收都必须完成 [机加工总图册同步与更新验收](machining-atlas.md)：最新安装件先给真实正视/侧视，再给其全部自制件加工图；万能柱集中一次，纯高度系列采用代表态并保留不同实际加工件。完整图册、逐变体 BOM、详细索引和页码必须与本次最新目录一致。默认增量补订：只新增、替换或删除受影响章节，未变正文、真实视图与验收记录直接沿用；目录和页码自动更新，不重画或重看全部图册。更新版验收并完成 NAS 回读后，直接删除本机及 NAS 的被替代旧图册、专用旧索引和交付副本，只留最新版；源 CAD、制造原图和必要来源/验收记录不在图册删除范围。没有实际同步或旧册未按规定删除，图册验收仍为未完成。此项为旁置交付协议，不向用户工程或元件 schema 添加审计字段，不替代既有云端验收和旧云端对象删除要求。


## 元件外观交付

新元件和样式修订遵守 [俯视图外观协议](topview-style.md)，使用 `zzlab-shaded-metal-v1`。交付真实 CAD 着色俯视图、冻结图框/源 SHA、渲染报告和旧新混合画布验收；外观验收独立于几何和加工验收，保持原点/安装孔/光学面/BOM/用户状态。


## 相邻小面包板净缝（2026-11-06 用户约定）

标准要求 `board-clearance-1mm-v1`：同一安装层相邻独立小面包板的真实板边最小净缝为 **1 mm**，不允许贴边或实体重叠；已有更大间隙保持。主承载板与其上小板的正常上下叠放不属于此间隙检查。

- 优先收缩有余量的板边，可单边退让1 mm或两侧合计退让1 mm。保持光学器件的世界坐标、角度、光高及全部现有安装孔的世界坐标和孔型；用户明确要求的整板移动单独实施、单独记录。不得通过缩放板和孔阵列制造缝隙。
- 以真实外轮廓、内凹缺口和板层高度逐对检查；不得只比较矩形包围盒，也不能用画布线宽或碰撞豁免代替物理净缝。
- 修边前后检查底座承托、通孔/沉孔的完整边壁、固定与工具可达。没有足够材料余量的边保留并列出例外，另行调整板形/布局；1 mm板间缝不等同于通用孔壁厚或加工公差。
- 参数板修边时保留原孔网基准；异形板或单边退让若当前JSON参数不能准确表达，登记独立的板型修订并保留原版本，不把旧STEP/PDF标为修边后的制造文件。
- JSON检查回执列出全部板对、最小净缝、修边量、原孔/光学基准保持情况与未完成项。仅完成本地轮廓/JSON验收时，明确CAD、加工图和Onshape同步状态；用户另有明确缝宽要求时以当次要求优先。

## 旧设计依赖（2026-11-12）

每次更新按用户明确选择执行：选择保留时，更新前冻结被替换的旧定义和必要CAD、图纸、预览、BOM依赖到 `library/history`；明确不保留时跳过本次历史归档；未说明选择先确认。保持可追溯的版本身份。旧工程继续解析/渲染，历史元件禁止新拖入/新增。清理必须同时核对当前、历史及工程引用；选择保留但历史保存或引用校验失败时，不执行会丢失旧版的替换。已有验收复用，仅核对本次恢复、版本解析和入口限制。
